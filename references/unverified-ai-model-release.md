# 未完全可验证的新模型发布素材处理

适用场景：用户给一篇“突发发布 / 性能炸场 / 全网热议”的参考文章，主题是新 AI 模型、新团队、新能力，但公开搜索不到足够硬的官方公告或主流英文媒体交叉验证。

## 核心原则

1. 不要把参考文章里的发布细节直接写成已坐实事实。
2. 先区分两层：
   - 可验证事实：官方页面、权威媒体、可访问 benchmark、公司博客、公开产品页。
   - 参考文叙事：模型名、跑分、限量预览、价格、合作伙伴数量、网友评论等。
3. 如果关键细节无法交叉验证，文章主线应从“报道这个事实”转为“分析这个叙事为什么会火、它反映了什么趋势”。
4. 可以保留参考文章的情绪点，但要用“文章里说 / 这套说法 / 如果属实 / 公开信息还不够硬”这类口径。

## 推荐写法

稳妥主线：

“某某模型真假先放一边，真正值得写的是：它戳中了行业正在发生的变化。”

常见可转向的趋势角度：

- 顶级模型能力越来越分层：免费用户、付费用户、企业客户、API 白名单拿到的东西不一样。
- 强模型越来越像受控基础设施，而不是普通网页按钮。
- 网络安全、自动化 Agent、漏洞修复等高风险能力，会天然触发监管和访问分级。
- 模型竞争从聊天框转向企业工作流、Codex/Agent、推理成本、芯片和合规。
- 普通用户真正该做的是把现有模型嵌进工作流，而不是只等下一个跑分。

## 文章内安全措辞

可以写：

- “我查了一圈，公开可验证的信息还不够硬，所以这事不能照单全收。”
- “但它为什么会火？因为它像真的，更准确地说，它符合最近这条行业趋势。”
- “如果这些细节属实，真正值得关注的不是跑分，而是访问方式变了。”
- “别急着把它当官方发布看，先把它当成一个行业信号看。”

避免写：

- “OpenAI 正式发布了 XXX”（除非已查到官方公告）
- “全网都在讨论”（除非搜索到足够多社区/媒体讨论）
- “政府已经要求审批”（除非有官方或权威媒体来源）
- “跑分登顶”（除非 benchmark 页面可访问并交叉验证）

## 执行检查清单

1. 抓取参考文章正文，记录标题、作者、链接、字数。
2. 搜索模型名 + 关键跑分 + 官方/英文关键词。
3. 搜索相关上游趋势素材，例如上一代模型、Codex、网络安全 benchmark、企业订单、芯片/推理成本。
4. 在 research.md 中单独写“公开可验证性”小节。
5. 初稿不要复刻参考文结构，用自己的主线重组。
6. 字数仍按参考文章 ±10% 控制，除非用户另有要求。
7. AI 味检测通过后，先把全文给用户审阅，等待确认再配图/封面/发布。

## 示例主线

参考文声称 GPT-5.6 Sol/Terra/Luna 限量预览，但搜索不到足够硬的官方交叉验证时，可以写：

“GPT-5.6 真假先放一边，真正的大新闻是：最强模型越来越不像一个人人可点开的网页按钮，而像一套被监管、企业合同、算力成本和安全分级共同控制的基础设施。”
