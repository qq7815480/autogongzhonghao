# 新发布 AI 模型/团队类公众号文章写法

适用场景：用户要求围绕刚发布或讨论热度上升的模型、AI 产品、模型团队写公众号文章，并要求全网搜索最新评测、讨论、团队介绍。

## 关键原则

1. 先把公开信息分层：
   - 已验证事实：公司/团队/融资/创始人履历/官方发布页/公开采访。
   - 官方口径：模型能力、参数、部署形态、benchmark、产品定位。
   - 媒体转述：融资报道、发布通稿、行业解读。
   - 第三方验证：Hugging Face/ModelScope 模型卡、GitHub、独立评测、社区实测。
   - 暂未验证：没有模型卡、没有权重、没有复现实测、只有一句“比肩/不输某模型”的宣传。

2. 写作时不要把官方口径写成事实。
   - 可以写“公开报道称”“团队给出的说法是”“目前更像产品定义/方向”。
   - 对缺少第三方复现的跑分、比肩旗舰模型等说法，要明确“先放一放”“仍需公开模型卡和第三方评测”。

3. 文章角度优先写“为什么值得关注”，而不是堆参数。
   - 例如 4B 小模型：重点可落在成本、端侧、agent 长周期运行、多智能体协作，而不是只写“参数小”。
   - 用普通人场景解释：个人助理、项目监控、店铺经营、家庭机器人、本地电脑常驻 agent。

4. 团队介绍要服务于判断。
   - 不只是列履历，要解释“为什么这帮人会做这个方向”。
   - 例如小冰团队背景，可连接到长期互动、人格、情感陪伴、多智能体协作、认知模型等产品路线。

5. 保持“谨慎但不泼冷水”的口吻。
   - 既承认方向有价值，也列清楚疑问：开放程度、评测方法、端侧边界、是否依赖大模型裁判、真实产品稳定性。
   - 避免标题党式“吊打”“震惊全球”，除非文章明确批判这种说法。

6. 对“有限预览 / 分阶段发布 / 受控访问”的前沿模型，发布方式本身就是主线。
   - 优先核对官方 Help Center、System Card / Deployment Safety Hub、官方发布页，再看媒体和社区。
   - 文章里明确区分：官方已确认、官方安全/访问口径、媒体转述、社区泄露、第三方榜单。
   - 如果模型已发布但不面向普通 ChatGPT 用户，不要写成“大家都能用了”；要写清楚“API/Codex/可信伙伴/未来几周开放”等访问条件。
   - 若涉及安全评估、政府协调、客户逐个批准、High/Critical 风险等级，别只写跑分，要把“谁能用、多少钱、被什么规则约束”写进主线。
   - 早期泄露中的上下文长度、代号、跑分、UI 实测，除非被官方或第三方榜单确认，否则用“传闻/社区转述/尚未在公开榜单看到”处理。

## 可复用结构

- 开头：先说为什么这次不是普通模型发布，以及自己为什么警惕。
- 第一部分：最容易传播的数字/卖点，但把真正意义讲透。
- 第二部分：解释核心概念，翻译成人话。
- 第三部分：团队背景，说明路线连续性。
- 第四部分：不看跑分，看成本/系统价值/真实场景。
- 第五部分：列出仍需验证的问题，避免神化。
- 结尾：提炼行业信号，用一句可传播的问题收束。
