# PIL 确定性配图兜底：正文图 + 微信封面

适用场景：本地生图 API 超时、限流、不稳定，或者文章里需要更精确的中文信息卡（价格、速度、流程、对比）时。

核心原则：不要因为一张 AI 图失败就停流程。先保留已成功生成的图片，其余正文图和封面可以用 Pillow 生成“暖色公众号信息卡”，确保文章能完整进入草稿箱。

## 工作流

1. 先按正常流程写 prompt 到 `prompts/`，这是复现记录。
2. 串行调用生图。若某张图超时：
   - 已生成成功的图复制到 `images/` 保留；
   - 剩余图改用 PIL 信息卡兜底；
   - 不要把“图片生成失败”写成长期规则，只记录“超时后用确定性兜底”。
3. PIL 正文图建议统一 1536×1024，暖色纸张背景，中文标题 + 3-5 个事实点/流程点。
4. 微信封面先生成 1536×1024 原图，但核心标题和元素必须放在中间安全区，再居中裁切到 1536×653（约 2.35:1）。
5. 插入 article.md 时必须使用绝对路径。
6. 发布前验证：
   - `grep -n '!\[' article.md` 必须能看到正文图；
   - 不能出现 `](images/` 相对路径；
   - `publish.py` 输出必须有“发现 N 张图片”和“图片处理完成：N/N 张成功上传”。

## 可复用 PIL 设计规格

- 正文图尺寸：1536×1024 PNG
- 封面输出：1536×653 JPG
- 背景：米白纸张色，如 `#FAF4E8`
- 主色：棕黑文字、橙色、浅蓝、红棕、绿色
- 字体优先：`/System/Library/Fonts/PingFang.ttc`
- 风格：暖色文艺杂志感、手绘边框、圆角卡片、信息清晰
- 不追求复杂插画，优先保证中文信息准确、可读、能上传

## 适合做成 PIL 卡片的内容

- 数字：价格、速度、比例、token 成本
- 流程：AI 生成 → Review → 测试 → Diff → 上线
- 对比：旧模型 vs 新模型、便宜模型 vs 强模型
- 结论卡：从跑分榜走向真实工作流、实用阶段信号

## 注意

PIL 兜底不是降低质量，而是保证发布流程稳定。对技术评论类公众号文章，清晰的信息卡往往比抽象 AI 插画更可靠。
