# 正文配图发布前检查

适用场景：用户确认文章后，进入配图、封面、排版、发草稿箱流程。尤其是文章是评论/新闻稿、没有参考原图时，也要显式决定是否需要 AI 正文配图，不能只做封面。

## 为什么要检查

一次实战中，文章已完成并经用户回复“没问题，继续”，但只生成了封面图就直接调用 `publish.py --input ... --cover ...` 创建草稿，导致正文没有任何配图。用户随后问“文章里忘记配图了吗？”。修复方式是补 3 张正文图、用绝对路径插入 `article.md`、重新发布新草稿。

## 发布前硬检查

在创建草稿前必须确认以下三件事：

1. `article.md` 是否有正文图片引用：
   - `grep -n '!\[' article.md`
   - 如果返回 0 条，必须问自己：这是用户明确同意的“纯文字文章”吗？
   - 如果不是纯文字文章，先进入阶段四生成正文配图，不要发布。

2. 图片路径是否是绝对路径：
   - `grep -n '](' article.md | grep '](images/'`
   - 命中说明仍有相对路径，必须修复成 `/Users/sun/.hermes/skills/wechat-publisher/sunwork/<date-slug>/images/...`。

3. `publish.py` 输出是否真的上传了正文图：
   - 正常输出应包含：`发现 N 张图片，开始处理...`、`正文图片上传成功:`、`图片处理完成：N/N 张成功上传`。
   - 如果输出没有“发现 N 张图片”，说明正文图没有被扫描到，即使草稿创建成功也不合格。

## 修复模式

如果已经发出无正文图草稿：

1. 不要修改旧草稿；直接补图后重新创建新草稿。
2. 为每个主要小节生成 2-4 张正文配图，保存到 `images/`。
3. 用绝对路径插入 `article.md`。
4. 重新跑 `ai_score.py`。
5. 重新调用 `publish.py --input ...`，确认输出显示正文图片上传成功。
6. 告诉用户以新 media_id 为准，旧草稿可删除。

## 经验规则

- “封面图已生成”不等于“文章已配图”。封面和正文图是两个独立交付物。
- 用户回复“继续”后，默认授权执行完整流程：正文配图 → 封面 → AI 味检测 → 草稿箱发布。
- 如果决定跳过正文配图，必须是因为文章类型确实适合纯文字，或用户明确要求不要配图。
