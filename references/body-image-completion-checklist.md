# 正文配图完成度检查清单

适用场景：公众号文章已经写好并创建过草稿，但用户要求“继续完成文章配图”“正文图没配完”“草稿正文图片失败/缺失”等。

## 核心原则

- 不要只修当前报错图片或补一两张图就结束；要按全文结构检查关键段落是否都有合适图片支撑。
- 对新闻评论/趋势分析类长文，正文图应服务文章节奏：解释概念、呈现入口变化、厘清模式边界、展示服务链路、给开发者行动清单、提示流量/权力变化。
- 如果参考文章包含产品截图、对比图、数据图、操作界面，优先保留原图；只有抽象观点或纯文字段落才用 AI 图。
- 所有插入 `article.md` 的图片路径必须是绝对路径，避免发布脚本跳过。

## 推荐检查流程

1. 先读文章目录和现有图片引用：
   - 用文章标题/小标题判断主要论点和转折点。
   - 用 `grep -n '!\[' article.md` 查看已有图片位置、alt 文案、路径。
2. 建立正文图覆盖点：
   - 开篇/核心概念：例如“微信 AI 能力网络”“不是聊天框，而是服务网络”。
   - 入口变化：例如“搜索/公众号/小程序/视频号/支付/客服入口被 AI 重排”。
   - 模式边界：例如“对话式 Agent 与服务型 Agent 的区别”。
   - 服务履约：例如“意图识别→调用服务→支付/预约/下单→结果返回”。
   - 开发者行动：例如“先接服务、再接账号体系、最后接交易闭环”。
   - 平台/流量分配：例如“用户意图被平台理解后，服务分发规则变化”。
3. 生成或收集图片：
   - 风格统一，尺寸一般 1536×1024；封面另走封面流程。
   - prompt 必须要求中文标题、中文标注，不能只有英文。
   - 尽量避免生成大量细小文字；要像信息图/白板示意图，可读性优先。
4. 插入图片：
   - 插到对应小节关键论断之后，不要堆在一起。
   - 用绝对路径：`/Users/.../sunwork/<article>/images/xx.png`。
5. 发布前验证：
   - `grep -n '!\[' article.md` 确认图片数量与分布。
   - `sips -g pixelWidth -g pixelHeight images/*.png` 确认图片可读、尺寸正常。
   - 运行发布/草稿脚本后，确认正文图片 URL 已替换为 `https://mmbiz.qpic.cn/`，而不是本地路径。
   - 如重建草稿，提醒用户查看最新草稿；不要误删旧草稿，除非拿到精确 media_id 并确认。

## 常见坑

- “继续完成配图”不是“继续执行刚才失败的一张图”，而是要做完成度审计。
- 只检查 images 目录有文件不够，必须检查 `article.md` 是否引用，且引用是否是绝对路径。
- 只创建新草稿不等于图片成功，必须确认转换后的 HTML 使用微信 CDN 图片地址。
- 微信草稿可能存在多个同标题版本，回复用户时要说“看最新草稿”。
