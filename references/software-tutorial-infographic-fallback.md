# 软件教程类信息图：截图式确定性兜底

适用场景：
- 文章介绍某个具体软件、功能或操作流程，用户要求“软件截图教程类”“要有使用界面截图”。
- 本地生图 API、Cockpit proxy、视觉分析等不稳定，无法用 gpt-image-2 生成可靠图。
- 已有信息图偏抽象，用户指出“不是软件截图教程类”或“段落没有配图”。

核心原则：
- 不要继续生成泛泛的 AI 应用场景图。
- 用确定性 HTML/SVG/Pillow 直接画“软件窗口截图风格”的信息图：macOS/Windows 窗口 chrome、菜单、按钮、表单、聊天框、进度条、鼠标光标、中文标注。
- 每个关键段落至少补一张对应图，避免只放一张总信息图。
- 文章图片引用必须用绝对路径，发布必须用 publish.py --input，让脚本上传正文图到微信 CDN。

推荐执行流程：
1. 先从文章结构中列出需要配图的位置：开篇总览、工作原理、适用任务、不适合/风险边界、结论或行动建议。
2. 总信息图用 1024×1536 纵向版，适合微信正文：4 步或 5 步流程，每步一块“软件界面截图”面板。
3. 分段正文图用 1536×1024 横向版：每张只讲一个小节，文字少、界面元素清楚。
4. 用 Pillow 或浏览器截图渲染方式生成 PNG，文件放在文章外部稳定目录或 sunwork/images 下。
5. 把 article.md 中原来的抽象图替换为新的绝对路径，并给缺图小节补齐图片引用。
6. 发布前检查：
   - grep -n '!\[' article.md 能看到所有正文图
   - 每个图片路径 os.path.exists(path) 为 true
   - 没有 ](images/ 相对路径
7. 重新运行 publish.py --input article.md --cover cover.png，不要用 --html。
8. 输出里必须出现“发现 N 张图片，开始处理...”和 N 张“正文图片上传成功”。如果没有，停止并修复路径。

Pillow 画法要点：
- 用系统中文字体，例如 /System/Library/Fonts/PingFang.ttc。
- 统一白蓝或暖色文档风格，避免花哨。
- 写出真实 UI 元素：窗口标题、菜单名、按钮名、表单字段、聊天消息、进度条。
- 软件名和操作词必须具体，例如“Codex”“Record a skill”“正在录制”“技能已生成”。
- 需要表现“教程截图”时，宁可用可读的仿真界面，也不要用抽象插画。

示例版式：
- 总标题：Codex Record & Replay 使用演示
- Step 1 录制：Codex 应用窗口，Plugins 菜单展开，高亮 Record a skill / 红色录制按钮。
- Step 2 演示操作：浏览器表单页面，左上角录制指示器，鼠标点击下载按钮。
- Step 3 生成技能：技能 markdown 文件，包含适用场景、输入参数、执行步骤，绿色“技能已生成”。
- Step 4 一句话回放：Codex 聊天界面，用户输入任务，Codex 显示正在执行和进度条。

注意：这是“精确中文信息卡 / 软件截图式兜底”，不是默认替代 baoyu 风格。若生图 API 可用且用户要 baoyu 手绘风，仍优先使用 baoyu 流程。
